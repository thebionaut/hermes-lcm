# Selective continuation recovery, integration contract

This implementation is independently staged on `ws/lcm-selective-1196`; it is not a production rollout. The sole new admission is `LCM_SELECTIVE_RETRIEVAL_SESSION_IDS`, an exact comma-separated session-ID allowlist, default empty. The existing `lcm_retrieve` controller remains unchanged for globally enabled adaptive retrieval; allowlisted sessions instead get an engine-isolated controller with `query_views=None`. Do not turn on assertions, embedding, query-view persistence or global adaptive retrieval for the pilot.

The answerer, not the summary model, chooses whether to recover. A `continuation-v1` summary may name `Omitted areas` and `Recovery references`; source handles must be supplied by actual source metadata, never invented by summarization. For a question whose answer requires a named missing slot, start `lcm_retrieve` with that slot, search only a bounded existing LCM tool, and finish using its exact source ref. With a known raw `store_id`, use `lcm_expand` with `include_exact_ref=true`; `lcm_load_session` supports the same flag for enumerated rows. The controller caps rounds at three and applies the existing argument, candidate-ref, and response limits. A source-backed answer already present in current context does not need a retrieval episode. A fact present only in a summary still needs source verification when exactness matters. A conflict requires exact source recovery; the summary is a cue, not evidence.

The tool path is read-only for historical messages. Its pilot controller neither opens a query-view store nor invokes a provider. Revoking the allowlist disables subsequent actions, including an episode started earlier. Sessions/profiles do not share an episode. If no valid source handle survives in the summary, use existing bounded `lcm_grep` or `lcm_load_session` to discover evidence; do not guess a store ID.

The continuation worker owns prompt fields and summary generation. Integration must merge the two independent config additions (`continuation_session_ids` and `selective_retrieval_session_ids`) without duplicate dataclass/env entries. No engine or background-compaction hook is required for this tool pilot. Qualify continuation summary quality separately: this recovery path does not make an unsafe summary contract eligible for rollout.
